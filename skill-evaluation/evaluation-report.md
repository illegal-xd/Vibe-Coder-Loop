## 4. 关键修改（候选，本轮未执行）

> 规范 §6：每个候选含问题/根因/文件/目的/验证。本轮仅 Propose，未 Probe/Compose（见 iteration-log.md）。

### 候选 P1 — 修复审计 `check` 性能/崩溃
- **问题**：`audit.sh check` 真实仓库崩溃（SIGILL exit 132）+ 72s 挂起。
- **根因**：`check_markdown_links()`（`scripts/audit.sh` 约 367–400 行）对每个 markdown 源行通过嵌套进程替换 `< <(printf '%s\n' "$line" | grep -oE '\]\([^)]+\)')` fork 一个 grep 子进程；全仓 63 md / 9408 行 → ~9408 forks；bash 3.2.57 fork 密度压力触发 SIGILL。
- **修改文件**：`scripts/audit.sh` `check_markdown_links()`。
- **目的**：复杂度 O(行数×fork) → O(文件数×fork)，全仓 <2s 且 exit 0。
- **验证**：C1（大文件不崩溃/快速）、G1（自测不退化）、A2（scan 不变）。**待执行对照。**

### 候选 P2 — 将 `skill:*` 规则内容纳入版本控制
- **问题**：完整规则内容仅存于 gitignored 快照/local DB，fresh clone 无法重建；与 README"唯一真实源"声明矛盾。
- **根因**：`.gitignore` 排除 `backup/snapshots/*`，仅 `.gitignore` 占位跟踪；SKILL.md 要求的 `restore snapshots/skill_memory_latest.json` 在 fresh clone 无文件可恢复。
- **修改文件**：`.gitignore`、`backup/snapshots/`（脱敏后入库）、`backup/memory_tool.py`（restore 忽略/重设 `db` 本机字段）。
- **目的**：fresh clone 可重建 `skill:*` 规则集 → 可移植性 I2 通过 + fail-closed 恢复动作可执行。
- **验证**：I2、E1、J1（口径调整后）。**须人工复核脱敏无凭证泄露。待执行对照。**

### 候选 P3 — 补 `runtime/exec/__main__.py`
- **问题**：`python3 -m runtime.exec` 不可执行（包缺 `__main__.py`）。
- **根因**：`runtime/exec/` 无 `__main__.py`，仅 `cli.py` 有 `main()`。
- **修改文件**：新增 `runtime/exec/__main__.py`。
- **验证**：E2。**待执行对照。**

### 候选 P4 — 审计自测增加真实规模回归
- **问题**：`test-audit.sh` 仅合成小仓库，永不暴露 D1/D4。
- **修改文件**：`scripts/tests/test-audit.sh`。
- **验证**：C1 自动化。**依赖 P1 先落地。**
