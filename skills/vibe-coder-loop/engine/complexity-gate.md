# Task Complexity Gate — 工程化程度判定

本文件定义 S4 Router 前置的工程化程度判定。Gate 在 Preflight/Decision 之后、模式选择之前执行，输出 **Level + Loop Depth**，Router 据此选择工作流。

> **Gate 只回答一个问题**：当前任务**需要多大程度的工程化流程**？——不是"我属于哪一级"。
> 文件数 / 行数 / 关键词一律是 **Signal（证据）**，**不得单独决定 Level**。

## 判定方法：三问 + 信号证据

```text
Q1 影响面      改动能波及多少已有行为 / 接口 / 数据 / 用户可见面？
Q2 不确定性    需求、现状、技术方案中有几处需要先验证才能动手？
Q3 可逆与风险  出错能否快速回退？是否触及数据 / 密钥 / 契约 / 用户资产？
```

三问的答案决定 Level；下表信号只用于**支持或修正**该判断，**任一信号不单独决定 Level**：

| 信号类 | 例 | 正确读法 |
|---|---|---|
| 变更形态 | 纯文本 / 注释 / 字符串 / 颜色 / 样式 / CSS / 主题 | 「**可能是**简单任务」——仍须 Q1/Q3 确认无影响面、无不可逆 |
| 变更规模 | 行数、文件数、函数数 | 「倾向 L1/L2」——规模大但影响面小 → **不升级** |
| 高风险域 | 认证 / 权限 / 金额 / 支付 / 删除 / 迁移 / 生产 / 部署 / schema / 加密 / 事务 | 「**提高关注度**：Q3 必须给出明确答案」——不机械升级 |
| 架构形态 | 重构 / 拆分 / 跨模块 / 数据流 / 接口契约 | 「倾向 L2/L3」——须由 Q1 确认是否真有模块交互 |

## 分级定义

| Level | 名称 | 判据（三问的典型结论） | 典型信号 |
|---|---|---|---|
| **Level 0** | 文字修改 | 影响面不含可执行逻辑；可逆性极高 | 改文案、修错别字、更新注释、调样式值 |
| **Level 1** | 单文件修改 | 影响面局限单文件；无需跨文件验证 | 单函数 bugfix、配置调整 |
| **Level 2** | 功能修改 | 影响面止于单模块；存在须先验证的不确定性 | 新增组件、API 调用、状态逻辑 |
| **Level 3** | 架构变化 | 影响面跨模块 / 数据流或接口契约变更 | 模块拆分、状态管理重构、数据层改造 |
| **Level 4** | 系统级变更 | 影响面跨项目 / 基础设施，且**不可逆** | schema 迁移、部署架构调整 |

> Level 体系与数量**保持现状**（不新增、不重编号）。表中判据是**典型结论**，不是绝对阈值。

## Loop Depth — 流程深度控制

Level 不仅控制入口，更控制**每个阶段是否激活、以什么形态激活**。核心原则：**Level 0/1 跳过/轻量化的是流程形式，不是安全约束本身**。

| 阶段 | Level 0（文字） | Level 1（单文件） | Level 2（功能） | Level 3/4（架构/系统） |
|------|----------------|------------------|----------------|----------------------|
| S1 Intent | 轻量（内联到 Code） | ✓ | ✓ | ✓ |
| S2 Preflight | 轻量（仅 Task→Memory Router 最小召回 + 消费清单记录，不执行代码向检查） | 轻量（仅 codegraph 定位） | ✓ | ✓ |
| S3 Decision | 条件触发（命中不可逆） | 条件触发 | 条件触发 | 条件触发 |
| S4 Router | ✓ | ✓ | ✓ | ✓ |
| S5 Clarify | 跳过 | 跳过 | ✓ | ✓ |
| S6 Design | 跳过 | 跳过 | ✓ | ✓ |
| S7 Plan | 跳过 | 跳过 | ✓ | ✓ |
| S8 Code | ✓ | ✓ | ✓ | ✓（多 subagent） |
| S9 Test | 跳过 | 轻量自测（≥1 项可观察验证：用例 / 类型检查 / 运行验证） | ✓ | ✓ |
| S10 Review | 内联文档子集 4 项（`policy/safety.md`「Level 0 文档修改约束子集」） | 轻量（硬约束 + 关键维度） | 完整 | 完整 |
| S11 Reflection | 跳过 | 跳过 | 条件触发 | 条件触发 |
| S12 Memory Evolution | 跳过（**出口内联**：收尾回写，见 `learning/memory/lifecycle.md`） | 跳过（**出口内联**同上） | ✓（收尾回写 + 有经验才沉淀） | ✓（同左） |
| S13 Complete | ✓（收尾清单：消费回写 + 仪表盘 + Checkpoint） | ✓（同左） | ✓（同左） | ✓（同左） |

### 安全不变量

**唯一事实源 = `kernel.md` §4.1「Loop Depth 安全不变量」**（此处不复述其四条声明）。

本表只补充一条**本层专属**口径：

**质量信号（#1/#2/#3 行数/参数）在 Level 0/1 不检查**——它们是 Review Signal，不是二值门；Level 0/1 出口只跑安全向检查（见 `policy/safety.md` §3）。

### 典型路径：Level 0 改按钮颜色

S1（内联）→ S2 轻量（最小召回 + 消费清单）→ S4 判级 → S8 改样式 → 出口内联安全向检查 → 通过输出 / 违反回退（1 轮上限）。跳过 S3/S5/S6/S7/S9/S11/S12（S10 以文档子集 4 项内联执行）。

### 典型路径：Level 1 修复单函数 bug

S1 → S2 轻量（codegraph 定位）→ S4 判级 → S8 修复 → 内联安全向检查 → S9 轻量自测（≥1 项可观察验证）→ S10 轻量审查 → 通过输出 / 未通过回退（1 轮上限）。跳过 S5/S6/S7/S11/S12。

## Level 0 细分：格式校对型 vs 内容写作型（Level 0-Doc）

同为 Level 0，两类任务的产出物与复核方式不同：

| 类型 | 判据 | 流程差异 |
|---|---|---|
| **格式校对型** | 修改/校对现有内容，无研究或总结语义 | 轻量 S2（最小召回 + 消费清单），S8 出口内联文档子集 4 项 |
| **内容写作型**（Level 0-Doc） | 含"整理 / 总结 / 新增章节 / 写作 / 研究沉淀"语义，或产出独立文档 | **保留轻量 S2**（同上）+ 素材/经验检索；S8 出口改**三维审查**（准确性 / 覆盖 / 格式） |

**边界**：Level 0-Doc 仅限文档 / 无逻辑变更；涉及代码修改（即使单文件）归 Level 1+。详细流程见 `engine/router.md`「Quick Loop 细则（L0 / L0-Doc / L1）」。

> 行数是**信号不是门槛**：长文档校对仍可能是格式校对型，短文档写作仍可能是内容写作型——按**语义**判，不按行数切。

## 输出格式

```text
### 工程化程度
- 程度：轻（直接做）／中（分析→实现→验证）／重（完整循环 + 规划）
- Level：<0-4> ｜ Loop Depth：<Quick / Standard / Full> ｜ 激活阶段：<上方矩阵对应列>
- 依据：<Q1/Q2/Q3 的结论，一句话>
- 存疑项：<尚无把握的点，后续暴露即升级>（无则省略此行）
```

## 与 Router 的衔接

**激活阶段唯一事实源 = 上「Loop Depth — 流程深度控制」矩阵**（逐阶段形态）。Level → Loop Depth 映射：L0 / L1 → **Quick Loop**；L2 → **Standard Loop**；L3 / L4 → **Full Loop**（含多 subagent 编排）。

Router 据本 Gate 输出的 Level 选择模式，不再重复判定规模。

## 不确定时的默认行为（progressive escalation）

信息不足时**不预套完整流程**，改为从最低成本路径起步、按证据升级：

1. 按当前判断的最低 Level 起步，标注 `[存疑起步]` + 存疑项
2. 出现下列任一 → **升级 Level 并继续**：发现跨文件引用 / 发现需先验证的假设被推翻 / 命中不可逆操作 / 验证失败
3. 禁止：因"不确定"而直接按 Level 2 套用完整流程（旧行为已废弃）
