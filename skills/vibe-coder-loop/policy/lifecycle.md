# Lifecycle Policy — 资产生命周期管理

本文件定义代码资产（函数、文件、组件、配置、注释）的生命周期管理：以分层权限替代"一律禁止删除"。**保护对象 = 用户既有资产**；本轮自产草稿不受归档强制（见下「适用范围」）；**记忆条目增删改查自主执行**（见文末「记忆条目删除义务」）。

## 生命周期状态机

```text
┌────────┐  Agent 可自主   ┌────────────┐  Agent 可自主   ┌──────────┐  用户明确指令   ┌────────┐
│ Active │ ──────────────→ │ Deprecated │ ──────────────→ │ Archived │ ──────────────→ │ Removed│
│ (在用) │   归档注释@Iteration │ (已废弃)    │   移至 archive/    │ (已归档)   │ 出清单+用户执行    │ (已删除)│
└────────┘                  └────────────┘                  └──────────┘  （Agent 不执行）      └────────┘
                                 ↑                                                                    ↑
                                 └──── TTL 90 天未引用 → Memory 标 stale → 提示用户审查 ────────────────┘
```

> **权限边界**：前两段转换 Agent 可自主完成；**Archived → Removed 不由 Agent 执行**——Agent 输出 Conflict Card + 「🗑 待删除清单」（含可执行命令），**物理删除由用户执行**。无用户指令时，Agent 不删除任何用户既有资产。

## 适用范围（保护对象 = 用户既有资产）

| 对象 | 定义 | Agent 权限 |
|---|---|---|
| **用户既有资产** | 本轮之前已存在，或用户明确表示要保留的代码 / 组件 / 注释 / 配置；**含用户明确要求移除的、含已归档的 `archive/` 文件** | 无用户指令 → 禁删，走归档；**用户明确指令 → 归档 + 输出「🗑 待删除清单」（含可执行命令）→ 物理删除由用户执行**（Agent 不执行） |
| **本轮自产草稿** | 本轮 Agent 新建、尚未经用户接受的实现（含重写本轮刚写的代码） | **可直接删除 / 覆盖 / 重写 / 重构**，不受归档注释强制（仍须说明变更） |
| **记忆条目** | delx-memory 的 key | 增删改查**自主执行**（常驻授权）——见文末「记忆条目删除义务」 |

> 资产保护的对象是**用户的代码**，不是"一切代码"。若把本轮自产草稿也纳入归档强制，结构会持续劣化（文件膨胀 → 触发行数信号 → 归档漂移）。
> 注：「用户已授权重构范围内被替换的实现」属**用户既有资产** → 走归档（`@Iteration` 注释 / `archive/`），不物理删除。

## 各阶段操作规范

### Active → Deprecated（Agent 可自主）

**触发条件**（任一命中，**仅适用于用户既有资产**；本轮自产草稿见「适用范围」）：

- 功能被新组件替代（用户当前任务引入新实现，旧实现不再需要）
- 需求变更导致废弃（旧功能不再被需求）
- 重构时旧实现被新结构取代

**操作要求**：

1. **不物理删除**：在旧实现位置加归档注释，原代码保留
2. **归档注释格式**：严格遵守 `@Iteration` 格式（见 `policy/safety.md`）
3. **计入文件行数**：归档注释参与 ≤ 300 行约束
4. **替代者声明**：归档注释中明确标注新替代者（函数/组件/文件名）
5. **不取消注释恢复**：归档后旧代码视为"冻结"，禁止在后续轮次取消注释重新启用（除非用户明确指令）

**示例**：

```typescript
// @Iteration: [v1] 旧支付逻辑被 PaymentService 替代，废弃 | 替代者: PaymentService
function oldProcessPayment(amount) {
  // ... 原实现保留 ...
}
```

### Deprecated → Archived（Agent 可自主）

**触发条件**（任一命中）：

- Deprecated 状态累计 ≥ 30 天（按 memory 中记录的归档时间）
- 同一文件中归档片段 ≥ 3 处，影响可读性

> **行数不是触发器**：文件行数阈值为 **Signal**（`policy/safety.md` §3 #2）——超限**不自动**触发归档，是否归档由 Agent 评估可读性收益后决定（口径见下「与约束分级的关系」）。

**操作要求**：

1. **移至 archive/ 子目录**：在原文件同级或上级创建 `archive/` 子目录，将归档代码移入
2. **源位置留指针注释**：

   ```typescript
   // @Archived: [v1] 旧支付逻辑已移至 archive/old-payment.ts
   ```

3. **archive/ 目录结构**：保持原模块的相对路径结构，便于追溯
4. **Memory 记录**：用 `delx-memory_memory_set` **直接写入**归档元数据（记忆操作常驻授权，无需用户确认）：
   - key=`archive:<文件路径>`
   - value={归档时间戳 + 原位置 + 归档原因 + 替代者}
   - tags=[archive, vibe-coder]
   - ttl_seconds=7776000（90 天，TTL 兜底用）

### Archived → Removed（Agent 不执行物理删除）

**触发条件**：用户在当前会话中明确指令"删除 xxx""移除 xxx""清理 archive"。
**边界**：Agent **不得**以"没人用了 / 太久了 / 清理性能"等自主推断删除（见下「禁止的自主删除」）；自主推断一律不构成删除依据。

**操作流程**（必须按序执行）：

1. **Intent 阶段冲突预检**：识别"删除"指令 → 标注 `[预仲裁]`
2. **Decision 阶段输出 Conflict Card**：
   - 用户意图: 删除 archive/xxx
   - 冲突红线: R1 资产安全
   - 不可逆性: 是 — 删除
   - 等价方案: [1] 输出待删除清单（用户执行删除） [2] 保持归档不动
   - 推荐选择: [1]（用户已明确指令）
   - Confidence: High（用户明确指令）
   - Evidence: E1（用户明确描述）
3. **输出「🗑 待删除清单」**：逐条列文件路径 + 归档时间 + 替代者，并给出可直接执行的命令（如 `rm archive/xxx` / `git rm`）——**Agent 到此为止，不执行删除**
4. **记忆侧同步**：相关 `archive:<路径>` 条目按「记忆条目删除义务」**自主删除**（核验归属 + 可回滚证据后执行，无需用户确认）
5. **用户执行后核验**（若用户回报已删）：确认文件不存在 + 更新备份/记录，输出 `🗑 已删除：<文件路径>（用户执行）`

**禁止的自主删除（无用户指令时）**：

- Agent 判定"这段代码没人用了" → 禁止删除
- Agent 判定"这个归档太久了" → 禁止删除
- Agent 判定"清理一下提升性能" → 禁止删除
- 任何 Agent 自主推断的删除动机 → 一律禁止（改走归档注释或列入待决策清单）

> 例外：**本轮自产草稿**（本轮新建、尚未经用户接受的实现）按上方「适用范围」处理，不受本条约束。

## 记忆条目删除义务（自主执行，无用户确认）

> 依据：**删除权限按对象划分**（代码资产不可删 / 记忆条目自主可删），见 `kernel.md` §2。记忆条目的删除**由 Agent 自主执行**（用户常驻授权），**不需要用户确认**；义务 = 下列两项技术自检。协议主源 = 本节；`learning/memory/lifecycle.md` 与 `learning/memory/promotion.md` 只留指针。

**两项义务（执行前自检，非用户确认）**：

| # | 义务 | 判据 |
|---|---|---|
| 1 | **归属为本方** | 跨 skill 或他方 `owner:*` 的键**不得删**，须 owner 确认；不确定即不删（降级为标记 `pending_removal`） |
| 2 | **可回滚证据已核验** | 快照 / git / 内容已迁移至替代键 —— 三选一且**实际核验**（非推断） |

**执行纪律**：

1. 两项义务任一不满足 → 降级为「标记 `pending_removal` + 列入 🗑 待删除清单」并在输出中标注原因
2. 单条删除直接执行；**批量 ≥5 条先输出「🗑 待删除清单」**再执行（可观测，**不阻塞**）
3. 删除后输出 `🗑 已删除：<keys>` + 重建备份快照（使 `verify` 一致）
4. 删除后做**引用扫描**：`memory_search` / FTS 反查旧键名，修掉导航类条目与规则条目里的陈旧指针（文件内引用另行 grep）
5. 回滚证据提示：**当日时间戳快照会被按天去重清理**，故不要依赖"当日快照"作为唯一回滚证据（用 git / 命名快照 / 内容已迁移）

**子 agent**：一律不执行删除——记忆写入/删除均归主 agent 汇总，防并发覆盖。

## TTL 兜底机制

`archive/` 下文件 90 天未被任何代码引用 → Memory 自动标 `stale` tag → 在下次 Preflight 阶段输出：

```text
⚠️ 归档文件待审查（90 天未引用）：
- archive/old-payment.ts（归档于 <归档日期>，原位置 src/payment.ts）
建议：[1] 用户确认后删除 [2] 重新激活（取消归档） [3] 继续保留
```

由用户决策，Agent 不自主删除。

## 与约束分级的关系

生命周期对应 `policy/safety.md` §3 的 **Hard** 项 #6（删除 / 覆盖用户既有资产）与 #9（归档注释格式）。
#2「文件 ≤ 300 行」是 **Signal**（`safety.md` §3）——超限**不自动**触发 Deprecated → Archived；是否归档由 Agent 判断可读性收益后决定。

## 子 agent 责任

子 agent 在 Code 阶段涉及资产生命周期操作时：

- **可自主执行**：Active → Deprecated（归档注释）、Deprecated → Archived（移至 archive/）
- **禁止执行**：任何物理删除——代码资产一律不删；记忆条目删除亦仅限主 agent 且须过「记忆条目删除义务」（子 agent 一律不执行记忆增删）
- 子 agent 违反 = 主 agent Code[N+1] 接管修复（同时回退违规操作，把删除改为归档）
- 子 agent 首步加载包见 `policy/safety.md` 第 5 节（统一协议：kernel + safety + lifecycle + confidence，兜底 `agent:vc_constraints`）
