# Design 阶段细则（骨架版）

[Phase: Design]
[Loop: 0]

> **骨架化说明**：三条专项规则与记忆交叉验证已下沉为 `skill:` 规则条目，加载时按需 `memory_get`；检索失败按本文件摘要降级执行。

本文件定义高层设计阶段的专项规则。Design 是白板级设计，不过度细节，但必须通过以下检查确保设计完整性。

## 核心输出要求

必须包含：核心模块划分 + 数据流描述 + 状态/副作用位置 + 技术选型理由（如有）。

## 规则 1：状态矩阵完整性检查

**触发**：涉及多状态操作按钮/功能时（任务状态流转、审批流、生命周期管理）

完整动作（主状态/子状态/操作矩阵/正交维度清单 + 反例）见 `skill:rules/design:state-matrix`（level:domain, permanent——加载全文执行）。

**要点**：列出所有主状态 → 对每个主状态列子状态 → 生成主状态 × 子状态完整操作矩阵 → 识别正交维度。**禁止**仅按主状态定义操作矩阵，遗漏子状态导致边界条件失控。

## 规则 2：先验证再假设

**触发**：编写"handleXxx 需要特殊处理"、"复制场景需要兼容"等假设性描述之前

完整动作（codegraph 调用链验证 + 判定 + 反例）见 `skill:rules/design:verify-first`（level:domain, permanent——加载全文执行）。

**要点**：找到相关函数完整调用链 → 检查现有守卫是否已覆盖 → 已覆盖标注"现有逻辑已覆盖，无需特殊处理"；未覆盖才设计特殊处理并说明理由。**禁止**未验证现有逻辑就假设需要特殊处理（过度设计比不足设计更危险）。

## 规则 3：多页面操作逻辑镜像同步

**触发**：列表页和详情页（或其他多个页面）共享相同操作逻辑时

完整动作（对照表/跨页检查/共享 composable + 记忆交叉验证判定标准）见 `skill:rules/design:mirror-sync`（level:domain, permanent——加载全文执行）。

**要点**：需求文档必须包含「多页面操作矩阵对照表」→ 任何一侧修改必须检查另一侧 → 理想抽取共享 composable。**禁止**独立演化导致行为不一致。

## 记忆交叉验证（细化）

出口前执行 `memory_search` 检索相关模块记忆（key 模式与判定标准见 `skill:rules/design:mirror-sync`「记忆交叉验证」节）：一致 → `[记忆验证通过]`；部分不一致 → `⚠️ 设计偏离已有架构` + 待决策清单；明显冲突 → **以当前代码事实为准**（`[Confidence: Medium]` + `[Evidence: E3(代码/图谱确认)]`），标注后继续并列入待决策清单，**不暂停**（记忆为 Advisory，见 `policy/confidence.md`）。
